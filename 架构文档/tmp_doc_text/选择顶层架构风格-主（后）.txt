中小餐饮数字化运营支撑系统（优化版 v2.3 — 安全与性能强化 2026落地版）
一、 顶层架构
架构风格：模块化单体 + 事件驱动 + 异步任务 + 安全/限流/监控加固
强化点
1.RLS（Row Level Security）增强
·  每条订单/数据表加 store_id/tenant_id 索引，使用 policy 过滤。
·  高峰期使用 pg_stat_statements 做 RLS 性能分析
·  必要时按 store_id 分区表，减少锁竞争。
JWT & Token 管理
·  access token 生命周期 5–15 分钟，refresh token 1–7 天。
·  rotate 时同时 revoke refresh token（Redis 黑名单管理）。
·  fastapi-users handler 可自定义 rotation。
3.Celery 安全/权限
·  Celery worker 专用低权限 Redis 用户（ACL 限定 queue）。
·  任务 payload 脱敏或加密，防止敏感数据泄露。
·  避免 Celery 暴露公网端口。
4.WebSocket/SSE 高并发控制
·  SSE fallback + 连接上限（每用户 5 个）。
·  Redis Streams 广播替代全量推送，减少单点压力。
·  前端订阅按门店/区域聚合，服务器端监控连接数/内存使用。
5.密钥管理
·  CI/CD secrets 通过 HashiCorp Vault / AWS Secrets Manager / sops-git 管理。
·  Docker/K8s 使用 secrets volume 替代 .env 明文存储。
测试覆盖增强
·  chaos 测试（Redis 连接 kill / 网络模拟抖动）。
·  RLS 策略测试（不同用户/门店查询）。
· 异常/边界条件事件流测试。
7.灾备/高可用
·  PostgreSQL 主从 + pgBouncer 连接池。
·Redis Sentinel/Cluster，Streams 消费组多 worker。
·  确保事件流和 DB 关键表高可用。
